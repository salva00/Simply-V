# SoC Simulation

Dual-backend simulation of the same RTL (filelist-swap HAL, see `sim_manifest.md`).

1. **Verilator** (open source, **active**) — the `xlnx_*` IPs are resolved by open sim models in `models/`.
2. **Vendor** — the `xlnx_*` IPs and crossbars (`XBAR_IMPL=XILINX`) are resolved by the real
   Xilinx sim-models. The vendor backend in use today is Vivado **xsim** (manual, not in CI,
   ibex only): the SV testbench + Vivado export + COE flow live in `xsim/`.
   **Questa Sim** is the intended vendor backend (pending license); its targets
   `sim_compile_simlib` and `sim_export_<ip>` are kept. `sim_compile_simlib_xsim` compiles the
   xsim libraries.

       make -C hw/xilinx sim BACKEND=xsim CORE=ibex TEST=hello_world

## Choosing the core

Set `CORE_SELECTOR` in `config/configs/common/config_system.csv`, then run:

    make sim TEST=hello_world          # from repo root

This works for every core with a Verilator cone: ibex, cv32e40p, picorv32, cv64a6 and
cv64a6_ara. The MicroBlaze-V cores have none; `config_sim` rejects them.

Config, bus crossbar wrappers included, is auto-regenerated on every `make sim` call — no
manual step needed. The firmware and RTL cone self-specialize to the selected core. The
tracked files the regen rewrites (`config.mk`, linker scripts, `simplyv_conf.h`, IP
`config.tcl`, crossbar wrappers, `rtl/generated/*`) are restored when the run ends, also on
Ctrl-C; a backup left by a killed run is restored by the next `make sim`. One sim per
checkout: a second concurrent one fails on a lock. `make sim` from the repo root is
equivalent to `make -C hw/xilinx sim BACKEND=verilator`, except that `TEST=smoke` skips the
config regen.

Quick override without touching the CSV (used by CI):

    make sim CORE=ibex       TEST=hello_world
    make sim CORE=cv32e40p   TEST=hello_world
    make sim CORE=picorv32   TEST=hello_world
    make sim CORE=cv64a6     TEST=echo
    make sim CORE=cv64a6_ara TEST=xlnx_cdma_examples

`CORE=` generates a temporary per-core CSV; `config_system.csv` is not modified.

### Validator constraints (when setting the core in config_system.csv by hand)

- **picorv32**: set `VIO_RESETN_DEFAULT=0` in the CSV; sys_parser rejects the default value.
- **cv64a6 / cv64a6_ara**: set `XLEN=64`; sys_parser rejects a 32-bit XLEN with a 64-bit core.

### Prerequisites

`settings.sh` is machine-agnostic. The caller must provide:

- `riscv32-unknown-elf-*` and `riscv64-unknown-elf-*` toolchains on `PATH` (rv32 cores use the
  32-bit chain; cv64a6/cv64a6_ara use the 64-bit chain).
- A Python environment where `python3` resolves to the simply-v conda env (the config flow calls
  `python3` unless `PYTHON` is set; `run_ci.sh` requires `PYTHON`).

## Usage (Verilator)

    source settings.sh embedded
    make -C hw/xilinx sim BACKEND=verilator TEST=smoke
    make -C hw/xilinx sim BACKEND=verilator TEST=hello_world
    make -C hw/xilinx sim BACKEND=verilator TEST=echo
    make -C hw/xilinx sim BACKEND=verilator TEST=interrupts
    make -C hw/xilinx sim BACKEND=verilator TEST=xlnx_cdma_examples

Each `TEST` (except smoke) builds `sw/SoC/examples/<TEST>` on demand and checks the UART
output against `stimuli/golden/<TEST>.uart.golden`. `interrupts` is built with `-DSIM_FAST`
(sim-only shorter timer/sleep periods; the FPGA build is unchanged).

Sim artifacts generated by the config flow live in `generated/` (gitignored); every
`make sim` regenerates them (`sim_defines.svh`, `verilator_embedded.f`, `siminc/`).

## Crossbar benches

Standalone benches on the in-tree crossbar RTL (no firmware):

    make -C hw/xilinx sim_verilator_xbar                  # simplyv_axi_xbar, 32-bit
    make -C hw/xilinx sim_verilator_xbar XBAR_DW=64        # simplyv_axi_xbar, 64-bit
    make -C hw/xilinx sim_verilator_xbar AXI4PC=1          # + ARM AXI4 protocol checker (needs XILINX_VIVADO)
    make -C hw/xilinx sim_verilator_axilite_xbar           # simplyv_axilite_xbar
    make -C hw/xilinx sim_verilator_mx_bridge              # MX memory-protocol bridge
    make -C hw/xilinx sim_xsim_xbar                        # same AXI4 crossbar, xsim + Xilinx AXI VIP (manual, needs Vivado)
    make -C hw/xilinx xbar_synth_check                     # Vivado out-of-context RTL elaboration (no project, no IP)
    make -C hw/xilinx simplyv_elab_check                   # Vivado RTL elaboration of simplyv with the Xilinx IPs (needs make ips)

## Local CI

    PYTHON=<python of the simply-v env> bash hw/xilinx/sim/ci/run_ci.sh

Runs the config flow unit tests (pytest), the Verilator `smoke` (which regenerates the sim
config) and the elaboration gate, then the crossbar benches
(`sim_verilator_xbar` 32/64-bit, `sim_verilator_axilite_xbar`, `sim_verilator_mx_bridge`;
with `XILINX_VIVADO` set, also `sim_verilator_xbar` 32/64-bit and
`sim_verilator_axilite_xbar` with `AXI4PC=1`), then the Verilator backend across all cores:
`ibex` and the 64-bit cores (`cv64a6`, `cv64a6_ara`) over the full embedded
suite (`hello_world echo interrupts xlnx_cdma_examples`), and the rv32 add-on cores
(`cv32e40p`, `picorv32`) over `hello_world`.
`sim_xsim_xbar`, `xbar_synth_check` and `simplyv_elab_check` need Vivado and are not in CI.

`cv64a6_ara` skips `xlnx_cdma_examples` by default: it is the long pole (~30 min — the idle
Ara netlist is evaluated every cycle) and adds no unique coverage (CDMA mem2mem does not touch
the vector unit, and the 64-bit CDMA path is already asserted by `cv64a6`). Set `SIM_CI_FULL=1`
to include it, or run it on its own:

    SIM_CI_FULL=1 bash hw/xilinx/sim/ci/run_ci.sh         # full matrix, incl. CDMA on ara
    make sim CORE=cv64a6_ara TEST=xlnx_cdma_examples      # just that run
