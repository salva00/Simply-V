# SoC Simulation

Dual-backend simulation of the same RTL (filelist-swap HAL, see `sim_manifest.md`).

1. **Verilator** (open source, **active**) — the `xlnx_*` IPs are resolved by open shims in `models/`.
2. **Vendor (Questa Sim, pending license)** — the `xlnx_*` IPs are resolved by the real Xilinx
   sim-models. The SV testbench + Vivado export + COE flow live in `xsim/` and are the base to
   adapt to Questa (SV-native). The `BACKEND=xsim` targets are kept but not in the active flow.

## Choosing the core

Set `core_selector` in `config/configs/common/config_system.csv`, then run:

    make sim TEST=hello_world          # from repo root; works for every core

Config is auto-regenerated on every `make sim` call — no manual step needed. The firmware
and RTL cone self-specialize to the selected core. `make sim` from the repo root is equivalent
to `make -C hw/xilinx sim BACKEND=verilator`.

Quick override without touching the CSV (used by CI):

    make sim CORE=ibex       TEST=hello_world
    make sim CORE=cv32e40p   TEST=hello_world
    make sim CORE=picorv32   TEST=hello_world
    make sim CORE=cv64a6     TEST=echo
    make sim CORE=cv64a6_ara TEST=xlnx_cdma_examples

`CORE=` generates a temporary per-core CSV; `config_system.csv` is not modified.

### Validator constraints (when setting the core in config_system.csv by hand)

- **picorv32**: set `VIO_RESETN_DEFAULT=0` in the CSV; sys_parser rejects the default value.
- **cv64a6 / cv64a6_ara**: set `XLEN=64`; sys_parser rejects a 32-bit XLEN with a 64-bit core.

### Prerequisites

`settings.sh` is machine-agnostic. The caller must provide:

- `riscv32-unknown-elf-*` and `riscv64-unknown-elf-*` toolchains on `PATH` (rv32 cores use the
  32-bit chain; cv64a6/cv64a6_ara use the 64-bit chain).
- A Python environment where `python3` resolves to the simply-v conda env (the config flow calls
  `python3`; CI exports `PYTHON` explicitly).

## Usage (Verilator)

    source settings.sh embedded
    make -C hw/xilinx sim BACKEND=verilator TEST=smoke
    make -C hw/xilinx sim BACKEND=verilator TEST=hello_world
    make -C hw/xilinx sim BACKEND=verilator TEST=echo
    make -C hw/xilinx sim BACKEND=verilator TEST=interrupts
    make -C hw/xilinx sim BACKEND=verilator TEST=xlnx_cdma_examples

Each `TEST` (except smoke) builds `sw/SoC/examples/<TEST>` on demand and checks the UART
output against `stimuli/golden/<TEST>.uart.golden`. `interrupts` is built with `-DSIM_FAST`
(sim-only shorter timer/sleep periods; the FPGA build is unchanged).

Sim artifacts generated by the config flow live in `generated/` (gitignored):
`make -C hw/xilinx sim_config_regen` regenerates them (`sim_defines.svh`, `sim_addrmap_pkg.sv`,
`verilator_embedded.f`, `siminc/`).

## Local CI

    bash hw/xilinx/sim/ci/compile_both.sh

Runs the Verilator backend across all cores: `smoke`, then `ibex` and the 64-bit cores
(`cv64a6`, `cv64a6_ara`) over the full embedded suite (`hello_world echo interrupts
xlnx_cdma_examples`), and the rv32 add-on cores (`cv32e40p`, `picorv32`) over `hello_world`.

`cv64a6_ara` skips `xlnx_cdma_examples` by default: it is the long pole (~30 min — the idle
Ara netlist is evaluated every cycle) and adds no unique coverage (CDMA mem2mem does not touch
the vector unit, and the 64-bit CDMA path is already asserted by `cv64a6`). Set `SIM_CI_FULL=1`
to include it, or run it on its own:

    SIM_CI_FULL=1 bash hw/xilinx/sim/ci/compile_both.sh   # full matrix, incl. CDMA on ara
    make sim CORE=cv64a6_ara TEST=xlnx_cdma_examples      # just that run
